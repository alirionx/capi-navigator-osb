The CAPI Navigator service broker passed its acceptance with a real Cloud Foundry: all packs of
the requirements (OSB-0 to OSB-4) are done.

## Accepted with Cloud Foundry (OSB4-F-03)

Tested on Cloud Foundry (CAPI 3.233, `cloudfoundry/kind-deployment` v0.26.0) against CAPI Navigator
0.17.0 with real clusters on AWS, the broker deployed with its Helm chart:

- `cf marketplace` shows one plan per blueprint with its parameters.
- `cf create-service` with worker pool parameters creates the cluster with its labels;
  `cf service` shows the progress ("control plane 0/1, workers 0/2 ready") until it succeeds.
- Parameters outside the blueprint's limits are refused, nothing is created.
- A second `cf create-service` with the same name is refused by Cloud Foundry.
- `cf create-service-key` hands out a kubeconfig that works with `kubectl get nodes`.
- `cf delete-service` deletes the cluster with cleanup.
- No token, password or kubeconfig in the broker's logs.
- Also used through the Stratos console (5.5).

## Fixes

- A refused order now names the violated limit, e.g. "The request does not fit the blueprint.
  parameters.workerPools.default.replicas: Too big: expected number to be <=5" (the reason CAPI
  Navigator gives in `details`).
- No more warning "secret file is readable by group or others" on Kubernetes: the chart's
  `fsGroup` makes the mounted secret files 0440 for the pod's own group, which is fine. The broker
  still warns if other users may read them.

## Install

- Image: `ghcr.io/alirionx/capi-navigator-osb:0.2.0`
- Helm chart: `oci://ghcr.io/alirionx/charts/capi-navigator-osb --version 0.2.0`
- Upgrade from 0.1.0: `helm upgrade … --version 0.2.0 --reuse-values`; no configuration changes.

## Requirements

- CAPI Navigator 0.16.0 or later, a technical user with `view`, `clusters.create`,
  `clusters.delete` and `clusters.kubeconfig`, and its API token.

## Known limits

- One instance is one cluster; no updates of plan or parameters.
- A binding is the admin kubeconfig: every developer of the space can read it, unbinding revokes
  nothing, it stays valid until the instance is deleted.
- Stratos 5.5 shows the kubeconfig of a service key unmasked, including the private key.
